## Reconciliation

Every figure below was recorded independently — by Person A, by hand, from the
evidence — before this pipeline could produce it. Two routes to the same number
is the strongest check available on this project.

**Security channel arithmetic for `s1_v2`:** 4688 (299) + 4624 (58) + 1102 (1)
+ 4625 (1) = **359**. Reproduces exactly.

**Ground-truth chain:** all three steps present in the written CSV, in order.

| step | timestamp | artifact |
|---|---|---|
| arrival | 2026-08-23T22:20:06.710763Z | `browser` |
| execution | 2026-08-23T22:57:15.832788Z | `prefetch` |
| clear | 2026-08-23T23:05:06.682356Z | `evtx.security` |

The execution timestamp is shared with `CONHOST.EXE` — Prefetch writes a batch
of records at one instant — so the reconciliation matches on the binary as well
as the time. Matching on timestamp alone would have passed against the wrong row.

**Contract invariants, checked on the serialised CSV rather than in memory:**

| collection | duplicate `event_id` | duplicate locator | bad `timestamp_type` | out of order |
|---|---|---|---|---|
| `clean_a` | 0 | 0 | 0 | no |

| `s1_v2` | 0 | 0 | 0 | no |

**Determinism:** a second independent run of the CLI produced byte-identical
CSVs for `clean_b` and `s1_v2`. Checked at file level, so it also covers CSV
quoting, field order and line endings.

recorded once and trusted.

## What is verified, and what is not

**Verified by execution:** the six parsers, the derived path fields, the rule
schema and its six rules, the feature layer and its exclusions, and the
acceptance test that gates the anomaly model. All of it runs against real
evidence in the gate, not against fixtures alone.

**Not verified here:** forensic-semantic correctness — whether an artifact
means what the parser claims it means. That is read from the artifact
specifications and from the ground truth, and it is Person A's side of the
work. The distinction matters: this record says the software does what it says,
not that what it says is the right thing to say.

**Recorded honestly:** the anomaly layer does not detect Scenario 1. The
execution ranks at the 52nd percentile among Prefetch rows and the log clear at
the 24th among Security rows, and neither is flagged. See
`docs/feature-decisions.md` section 6 — this is a property of a 4,608-byte
stand-in that runs once, not a fault in the model, and an earlier configuration
that *did* appear to detect it was measurably reading artifact mix instead.
